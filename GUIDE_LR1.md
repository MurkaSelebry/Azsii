## 1. О чём задание простыми словами

Нейросеть-классификатор получает картинку и говорит, что на ней: цифра «7», «кошка», «грузовик».
Оказывается, почти любую такую сеть можно обмануть, если **чуть-чуть** изменить картинку. Человек изменений
не заметит, а сеть уверенно выдаст неправильный ответ. Такая испорченная картинка называется
**состязательным примером** (adversarial example), а способ её построить — **состязательной атакой**.

Почему это важно для безопасности ИИ:

* знак «STOP» с наклейками автопилот может принять за «ограничение скорости»;
* фильтр спама или вредоносного кода можно обойти, слегка изменив входные данные;
* система распознавания лиц может пропустить «не того» человека.

Чтобы защищаться, сначала нужно уметь **измерять**, насколько модель уязвима. Этим лабораторная и занимается:

1. Берём готовый учебный проект ([EEL6812_DeepFool_Project](https://github.com/ewatson2/EEL6812_DeepFool_Project)).
   Его авторы повторили статью про DeepFool и выложили код и обученные веса.
2. Загружаем 4 обученные модели:
   * **FC-500-150** и **LeNet** — распознают рукописные цифры (датасет **MNIST**);
   * **Network-in-Network (NiN)** и **LeNet** — распознают 10 классов объектов (датасет **CIFAR-10**).
3. Атакуем их двумя способами:
   * **FGSM** — быстрая, «грубая» атака в один шаг;
   * **DeepFool** — итеративная атака, которая ищет **минимальное** изменение, нужное для обмана.
4. Считаем, какой процент картинок удалось «сломать» и насколько сильно пришлось их менять.
5. Смотрим глазами, как выглядят атакованные картинки.
6. **Главная исследовательская часть (п. 14):** меняем силу атаки FGSM (`eps` = 0.001, 0.02, 0.5, 0.9, 10)
   и выясняем, как это влияет на результат: где влияние есть, где его нет и почему.

## 2. Словарик

| Термин | Что значит |
|---|---|
| **Классификатор** | Модель, которая относит вход к одному из классов (здесь 10 классов) |
| **Логит (logit)** | «Сырой» выход сети для каждого класса, до softmax. Больше логит — сеть сильнее «за» этот класс. Может быть любым числом |
| **Softmax** | Превращает логиты в вероятности (неотрицательные, в сумме 1) |
| **Функция потерь (loss)** | Число «насколько сеть ошиблась». Здесь кросс-энтропия |
| **Градиент по входу ∇ₓL** | Показывает, как изменится loss, если чуть изменить каждый пиксель. При обучении берут градиент по **весам**, при атаке — по **картинке** |
| **Возмущение (perturbation) r** | То, что прибавляем к картинке: `x_adv = x + r` |
| **Норма L2, ‖r‖₂** | «Длина» вектора возмущения: корень из суммы квадратов |
| **Норма L∞, ‖r‖∞** | Максимальный модуль одного элемента. У FGSM все элементы равны ±eps, поэтому ‖r‖∞ = eps |
| **Нормализация** | `x_norm = (x − mean) / std`. Делается перед подачей в сеть |
| **Клиппинг (clamp/clip)** | Обрезка значений до допустимого диапазона, чтобы картинка оставалась «картинкой» |
| **White-box атака** | Атакующий знает модель целиком (архитектуру и веса) и может считать градиенты. Обе атаки в лабораторной такие |
| **Untargeted атака** | Цель — любая неправильная метка (а не конкретная). Обе атаки здесь такие |
| **Test error** | Доля тестовых картинок, классифицированных неверно |
| **Robustness ρ_adv** | Средняя относительная величина возмущения ‖r‖₂/‖x‖₂ (подробнее в разделе 6) |
| **Seed** | «Зерно» генератора случайных чисел. Одинаковый seed даёт одинаковые случайные числа и воспроизводимый результат |

## 3. Что нужно понимать до начала

### 3.1. Тензоры и формы

Картинки в PyTorch — тензоры формы `[N, C, H, W]`: N — сколько картинок в батче, C — каналы (1 для
ч/б MNIST, 3 для RGB CIFAR), H×W — размер (28×28 или 32×32). Батч из 64 картинок CIFAR — это тензор `[64, 3, 32, 32]`.

### 3.2. Нормализация и обратное преобразование

`transforms.ToTensor()` переводит пиксели из 0..255 в **[0, 1]**. Затем `transforms.Normalize(mean, std)`
делает `(x − mean)/std`:

* MNIST: `mean = std = 0.5` → диапазон **[−1, 1]**;
* CIFAR-10: `mean ≈ [0.49, 0.48, 0.45]`, `std ≈ 0.2` → диапазон примерно **[−2.4, 2.75]** (ширина ≈ 5).

Модели обучались на **нормализованных** данных, поэтому и атаки работают в нормализованном пространстве.
Для показа картинки нужно преобразование назад, `*_tf_inv`. Оно сделано двумя `Normalize` подряд:

* `Normalize(mean=0, std=1/std)` — это `x / (1/std) = x·std`;
* `Normalize(mean=−mean, std=1)` — это `x − (−mean) = x + mean`.

Получается `x·std + mean`, исходная картинка в [0, 1].

### 3.3. Клиппинг: функция `get_clip_bounds`

Атака не должна выводить пиксели за пределы допустимого: яркость не может быть меньше 0 или больше 1.
`get_clip_bounds(mean, std, dim)` пересчитывает границы [0, 1] в нормализованное пространство:
`min = (0 − mean)/std`, `max = (1 − mean)/std`. Получаются тензоры формы `[C, dim, dim]`, свой для каждого канала.
Затем в атаке делается `torch.max(torch.min(x_adv, clip_max), clip_min)`, то есть обрезка.

**Это ключ к пониманию п. 14:** при большом `eps` почти все пиксели упираются в эти границы.

### 3.4. Градиент по входу

При обучении считают `∂L/∂w` и сдвигают веса так, чтобы loss **уменьшался**. При атаке веса заморожены.
Считаем `∂L/∂x` и сдвигаем **картинку** так, чтобы loss **рос**. Технически: `x.requires_grad = True`, прямой проход,
`loss.backward()`, и в `x.grad` лежит градиент по пикселям.

### 3.5. `model.eval()`

В NiN есть `Dropout`. В режиме обучения он случайно «выключает» нейроны. `model.eval()` отключает его,
чтобы ответ модели был детерминированным. `evaluate_attack` и `display_attack` вызывают `model.eval()` сами.

## 4. Атака FGSM

**FGSM** (Fast Gradient Sign Method, Goodfellow и др., 2014).

### Идея

Если бы сеть была линейной, то быстрее всего loss растёт при сдвиге в направлении градиента.
FGSM берёт от градиента только **знак** и делает **один** шаг размера `eps` по каждому пикселю:

```
x_adv = clip( x + eps · sign(∇ₓ L(f(x), y_true)), x_min, x_max )
```

* `sign(...)` — каждый пиксель сдвигается ровно на +eps или −eps (L∞-ограничение);
* `y_true` — **истинная** метка: увеличиваем ошибку относительно правильного ответа;
* `clip` — возвращаем в допустимый диапазон.

### Код из `utils/project_utils.py` с пояснениями

```python
def fgsm(model, clip_min, clip_max, images, labels, eps=0.007):
    images_grad = images.detach()          # копия без истории вычислений
    images_grad.requires_grad = True       # хотим градиент по пикселям
    loss_fn = nn.CrossEntropyLoss()
    outputs = model(images_grad)           # логиты
    loss_fn(outputs, labels).backward()    # градиент loss по картинке
    images_adv = images.detach() + eps * images_grad.grad.sign()   # шаг FGSM
    images_adv = torch.max(torch.min(images_adv, clip_max), clip_min)  # клиппинг
    images_pert = images_adv - images.detach()   # фактическое возмущение (после клиппинга!)
    with torch.no_grad():
        outputs = model(images_adv)
    confs_adv, labels_adv = outputs.max(dim=1)   # «уверенность» (= логит) и предсказание
    return images_adv, images_pert, confs_adv, labels_adv
```

### Свойства

* **Очень быстрая:** один прямой и один обратный проход на батч (микросекунды на картинку).
* **Не минимальная:** все пиксели сдвигаются на одинаковую величину, даже если для обмана хватило бы меньшего.
* Результат **полностью определяется `eps`**: мал `eps` — атака не срабатывает, велик — картинка превращается в шум.

## 5. Атака DeepFool

**DeepFool** (Moosavi-Dezfooli и др., 2016). Цель — найти **наименьшее** (по L2) возмущение, которое меняет ответ сети.

### Интуиция для двух классов

Пусть классификатор линейный: `f(x) = wᵀx + b`, класс определяется знаком f. Граница решения — гиперплоскость `f(x) = 0`.
Кратчайший путь от точки до гиперплоскости — перпендикуляр к ней:

```
r* = − f(x) · w / ‖w‖²,       его длина ‖r*‖ = |f(x)| / ‖w‖
```

### Многоклассовый случай

Классов 10, у каждого свой логит `f_k(x)`. Текущий класс `k₀` (предсказание сети). Для каждого другого класса k:

```
w'_k = ∇f_k(x) − ∇f_k₀(x)       (градиент разницы логитов)
f'_k = f_k(x) − f_k₀(x)          (разница логитов, < 0, пока побеждает k₀)
```

Расстояние до границы «k₀ против k» в линейном приближении равно `|f'_k| / ‖w'_k‖`. Выбираем **ближайшую** границу:

```
l̂ = argmin_k  |f'_k| / ‖w'_k‖₂
r_i = (|f'_l̂| / ‖w'_l̂‖₂²) · w'_l̂
```

Сеть нелинейна, поэтому одного шага обычно мало. Шаг повторяем, накапливая `r̂ = Σ r_i`, пока класс не сменится
(или пока не кончатся `max_iters = 50` итераций). В конце добавляется **overshoot**: `x_adv = x + (1 + 0.02)·r̂`.
Без него точка оказалась бы ровно на границе, и класс мог бы не смениться.

### Как это сделано в коде (самое хитрое место)

Для шага нужны градиенты **всех 10 логитов** по картинке, то есть 10 обратных проходов. Авторы делают это за один
проход таким трюком:

1. Картинка копируется 10 раз: `x_batch = x.repeat(10, 1, 1, 1)`. Это `deep_batch_size = 10` из `deep_args`.
2. Считается `NLLLoss(reduction='sum')(f_k, k_batch)`, где `k_batch = [0, 1, …, 9]`. Для j-й копии NLLLoss на «сырых»
   логитах даёт просто `−f_j(x_j)`. Сумма по копиям: `−Σ_j f_j(x_j)`.
3. После `backward()` в `x_batch.grad[j]` оказывается `−∇f_j`. Минус убирается (`w_k.append(-x_batch.grad...)`),
   и получаются градиенты всех классов сразу.

Остальное — прямое переложение формул выше. Две детали:
* к шагу добавляется `+1e-4` (авторы проекта пишут, что так нужно меньше итераций);
* после каждого шага делается клиппинг.

При `labels=None` (так и вызывается, `has_labels=False`) за `k₀` берётся **предсказание** модели, а не истинная метка.
То есть атака старается сменить ответ сети, каким бы он ни был.

### Сравнение атак

| | FGSM | DeepFool |
|---|---|---|
| Шагов | 1 | итеративно (обычно 2–5, максимум 50) |
| Норма | L∞ (каждый пиксель ±eps) | L2 (минимальный вектор) |
| Параметр силы | `eps` задаёт размер шага | нет, ищется минимальный шаг (есть только `overshoot`) |
| Скорость | микросекунды на картинку | миллисекунды–секунды на картинку |
| Размер возмущения | большой, «шум» по всей картинке | очень маленький, почти незаметен |
| Использует метку | истинную | предсказанную |
| Для чего | быстрая атака, adversarial training | точная оценка стойкости ρ_adv |

## 6. Метрики: что печатает `evaluate_attack`

```
FGSM Test Error : 87.08%          ← доля картинок, на которых модель ошиблась ПОСЛЕ атаки
FGSM Robustness : 1.56e-01        ← среднее ‖r‖₂ / ‖x‖₂
FGSM Time (All Images) : 0.15 s   ← суммарное время атаки
FGSM Time (Per Image) : 14.99 us  ← на одну картинку
```

* **Test Error** считается относительно **истинных** меток по всем 10 000 тестовым картинкам. Сюда входят и картинки,
  на которых модель ошибалась **без атаки**. Поэтому даже при eps → 0 ошибка не ноль, а равна ошибке на чистых данных.
* **Robustness** (в статье ρ̂_adv) = среднее по картинкам `‖r‖₂ / ‖x‖₂`, где обе нормы считаются в **нормализованном**
  пространстве.
  * Для **DeepFool** это настоящая мера стойкости модели: «на сколько процентов в среднем нужно изменить картинку, чтобы
    обмануть сеть». **Чем больше, тем стойче модель.**
  * Для **FGSM** число почти не говорит о модели. Возмущение — это ±eps в каждом пикселе, поэтому ‖r‖₂ ≈ eps·√(число пикселей),
    и значение определяется в основном выбранным `eps` (и клиппингом).
* `evaluate_attack` пишет результаты по батчам в CSV и печатает итог. Robustness там — среднее из средних по батчам.

### П. 5–6. Seed

```python

```

От seed зависят: разбиение `random_split` (какие 10 000 картинок уйдут в валидацию), случайные аугментации

Разный seed у студентов нужен, чтобы картинки в отчётах различались.

### П. 11. NiN на CIFAR-10

```python
fgsm_eps = 0.2
model = Net().to(device)
model.load_state_dict(torch.load('weights/clean/cifar_nin.pth', map_location=torch.device('cpu')))
evaluate_attack('cifar_nin_fgsm.csv', 'results', device, model, cifar_loader_test,
                cifar_min, cifar_max, fgsm_eps, is_fgsm=True)
evaluate_attack('cifar_nin_deepfool.csv', 'results', device, model, cifar_loader_test,
                cifar_min, cifar_max, deep_args, is_fgsm=False)
if device.type == 'cuda': torch.cuda.empty_cache()
```

* `Net()` создаёт архитектуру со случайными весами, `load_state_dict(torch.load(...))` подгружает обученные веса.
  `map_location` говорит, на какое устройство грузить тензоры весов.
  `load_state_dict` копирует их в параметры модели, а модель уже стоит на `device`.
* `evaluate_attack(имя_csv, папка, device, model, loader, clip_min, clip_max, параметры_атаки, is_fgsm)`.
  Для FGSM параметр — число `eps`, для DeepFool — список `deep_args`.
* `torch.cuda.empty_cache()` освобождает кэш видеопамяти между экспериментами.

`eps = 0.2` для NiN и `0.1` для LeNet авторы выбрали так, чтобы FGSM давал ошибку порядка 80–90%.

### П. 13. Визуализация

`display_attack(device, model, test_dataset, inv_tf, clip_min, clip_max, fgsm_eps, deep_args, has_labels=False,
l2_norm=True, pert_scale=1.0, fig_rows=2, fig_width=25, fig_height=11, label_map=None)`:

* берёт `fig_rows = 2` случайные картинки;
* атакует их FGSM и DeepFool;
* рисует 5 колонок: **Original | Adversarial (FGSM) | Adversarial (DeepFool) | Perturbation (FGSM) | Perturbation (DeepFool)**;
* подписи: `true label`, `pred label`, `conf score` (это **логит**, а не вероятность), `robustness` (‖r‖/‖x‖ для этой
  картинки), `eps`, `overshoot`, `iters` (сколько итераций понадобилось DeepFool);
* `pert_scale` усиливает возмущение **только при отрисовке**: возмущение DeepFool очень мало, при 1.0 оно почти
  не видно и выглядит серым фоном;
* `label_map=cifar_classes` подменяет номера классов названиями.

Возмущения рисуются через `inv_tf`, то есть `r·std + mean`. Поэтому «нулевое» возмущение выглядит серым
(значение mean), а не чёрным.

Дополнительно (не по заданию, для полноты отчёта) таким же `evaluate_attack` прогоняются модели MNIST.

### П. 14. Исследование `eps`

Подробно в разделе 11. Кратко:
* `fgsm_eval` — своя функция оценки. Внутри она вызывает ту же `fgsm` из проекта, но **возвращает** числа, а не только

## 9. Сложные моменты и грабли

1. **Готовые CSV в `results/` (самая коварная ловушка).** `evaluate_attack` сначала проверяет, есть ли уже CSV с таким
   именем. Если файл есть и в нём все 157 батчей, атака **не запускается**: функция читает файл и печатает метрики.
   Так сделано, чтобы долгий расчёт можно было продолжить после обрыва. Но в репозитории авторы оставили свои CSV,
   поэтому ноутбук «по заданию» за долю секунды печатает **чужие** цифры. Признак — подозрительно быстрое выполнение
   ячейки DeepFool. Решение: перенести `results/` в `results_author/` (сделано в ноутбуке) или передать другое имя файла.
   Тот же механизм бьёт и при повторном запуске: поменяли `eps`, а имя файла оставили, и получили старый результат.
2. **`deepfool` падает на CPU.** В коде проекта стоит `device = images.get_device()`. На GPU это 0, на CPU в
   современных PyTorch это −1, и `torch.arange(...).to(-1)` даёт `RuntimeError: Device index must not be negative`.
   В Colab с T4 ошибки нет, но если забыть включить GPU, пп. 11–13 упадут. В ноутбуке сразу после `%cd` стоит ячейка,
   которая заменяет эту строку на `device = images.device`. Это работает везде и на результат не влияет.
3. **`deep_args` не определён в тексте задания.** Без него будет `NameError`. Значение берётся из ноутбука авторов.
4. **`torch.load` без `map_location`** в п. 13. Если веса сохранены с GPU, а GPU в сессии нет (забыли включить T4),
   загрузка упадёт с `RuntimeError: Attempting to deserialize object on a CUDA device...`. В ноутбуке везде стоит
   `map_location=device`.
5. **`eps` задаётся в нормализованном пространстве, а не в пикселях.** `eps = 0.2` на MNIST — это сдвиг на 0.1
   яркости (0.2 × std 0.5), а на CIFAR-10 — на 0.04. Сравнивать eps между датасетами «в лоб» нельзя.
6. **Клиппинг «съедает» часть возмущения.** Возмущение `images_pert` считается **после** клиппинга. Фон MNIST равен −1,
   то есть уже на нижней границе. Если знак градиента там «−», пиксель не сдвинется. Поэтому при больших eps реальное
   изменение меньше `eps`. Из-за этого возникает насыщение в п. 14.
7. **`conf score` — это логит, а не вероятность.** Он может быть 15 или 40, это нормально.
8. **Test Error у DeepFool не 100%**, хотя атака «всегда доводит до смены класса». Причины:
   (а) атака идёт против **предсказания**, а ошибка считается против **истинной метки**. Если модель изначально
   ошибалась, DeepFool может «перебросить» картинку как раз в правильный класс;
   (б) клиппинг иногда не даёт дойти до границы за 50 итераций.
9. **Robustness для FGSM почти не зависит от модели.** Он определяется `eps`, а о стойкости модели говорит
   robustness DeepFool.
10. **`num_workers=4`** в Windows вне Jupyter требует `if __name__ == '__main__':`; в Colab/Linux проблем нет.
   В Colab может появиться предупреждение о числе воркеров, оно не критично.
11. **`display_attack` показывает случайные картинки** (`shuffle=True` внутри), поэтому при каждом запуске они разные.
    Зафиксировать можно, только запуская ноутбук целиком сверху вниз с тем же seed.
12. **DeepFool долгий.** На GPU T4 — минуты на модель, на CPU — десятки минут (NiN дольше всех).
    В Colab не закрывайте вкладку, иначе сессия отвалится.
13. **Скачивание CIFAR-10** (~170 МБ) с сайта Торонто иногда идёт очень медленно. Если зависло, перезапустите ячейку
    или скачайте архив вручную в `datasets/cifar-10/`. torchvision проверит MD5 и не будет качать заново.
